The ten VERIFIED entries most worth fixing first, most severe first (Claude's ranking: crashes and memory corruption on ordinary input, then silent damage to the model, then silently wrong results):

1. `handle_read_draw_probe_dots()` (`src/generic-objects.cc:1016-1023`): indexes an emptied vector on any re-read of probe dots, and wipes every generic object.
2. `remove_omega_peptide_restraints()` (`geometry/protein-geometry.cc:2197-2202`): `erase(it)` then `it++`; runs off the end when the omega is the last torsion. Introduced by the 53c14bdf3 fix.
3. `highly_coordinated_waters_py()` (`src/c-interface-waters.cc:500-502`): with two or more hits the same two lists are stolen into several result lists, which corrupts refcounts.
4. `residues_near_residues_py` (`src/c-interface-info.cc:806`): NULL slots in the returned list whenever an input spec matches no residue; crashes when Python iterates it.
5. The eight functions with no `imol >= 0` check (e.g. `set_map_is_difference_map`, `average_temperature_factor`, `mask_map_by_molecule`): the -1 from a failed read indexes `molecules[]` out of range.
6. `trim_by_map()` (`src/molecule-class-info-other.cc:4861-4868`): the backup is taken after the trim, so the deleted atoms cannot be recovered with undo. `delete_waters()` and `add_residue_with_atoms()` have no backup at all.
7. `superpose_with_atom_selection()` (`src/c-interface-superpose.cc:244`): in copy mode the reference cell and symmetry are written to the original molecule, not the copy.
8. `find_water_baddies_AND()` (`src/molecule-class-info-other.cc:7003`): the density test is inverted, so AND mode flags the well-fitting waters.
9. `make_map_from_cif_2fofc()` (`src/molecule-class-info-maps.cc:3043`): silently makes a sigmaA map.
10. `save_state()` vs `run_state_file*()` (`src/graphics-info-state.cc:867`, `src/c-interface.cc:8076`): state is written to the XDG state directory and looked for in the cwd, so a saved state is never found.

- **FIXED** (branch `fix-api-docs-bugs`) `geometry/protein-geometry.cc:2197-2202` `remove_omega_peptide_restraints()`: since 53c14bdf3 removed the `break`, `erase(it)` is followed by `it++` on the invalidated iterator. That is UB, and when the omega is the last torsion `it` steps past `end()` and the loop runs off the end. Fix: `erase(remove_if(...), end())`, as the comment in the code already suggests.
- **FIXED** (branch `fix-api-docs-bugs`) `src/c-interface.cc:7659-7664` `residue_spec_make_triple_py()`: puts the borrowed references from `PyList_GetItem()` straight into a new list with `PyList_SetItem()` (which steals), so the three items are owned by two lists on one reference each.
